#  Приложение для анализа транзакций
Приложение будет генерировать JSON-данные для веб-страниц,
формировать отчеты в формате Excel, а также предоставлять другие сервисы.

По состоянию на 18.02.2026 проект находится в разработке.

Структура приложения:
1. Веб-страницы:
- Главная
- События
2. Сервисы:
- Выгодные категории повышенного кешбэка
- Инвесткопилка
- Простой поиск
- Поиск по телефонным номерам
- Поиск переводов физическим лицам
3. Отчеты:
- Траты по категории
- Траты по дням недели
- Траты в рабочий/выходной день

## Установка приложения
1. На данной стадии разработки для использования приложения необходимо установить `PyCharm`.
2. Клонируйте репозиторий с [GitHub](https://github.com/Dasha0Ramzer/transaction-analysis-application).
3. Установите зависимости:
```commandline
poetry install
```
4. Получите API-ключи на [api.apilayer.com](https://api.apilayer.com) и на [api-ninjas.com](https://api-ninjas.com),
скопируйте файл `.env.example` и вставьте свои API-ключи.
5. В файл `userr_settings.json` вставьте пользовательские валюты и акции.
6. В папку `data/` добавьте файл с операциями под названием `operations.xlsx`.

## Разработка
Основные функции для генерации JSON-ответов реализованы в отдельном модуле `views.py`.

Вспомогательные функции реализованы в модуле `utils.py`.

Сервисы реализованы в отдельном модуле `services.py`.

Отчеты реализованы в отдельном модуле `reports.py`.

По состоянию на 18.02.2026 в проекте реализованы следующие функции:

- **Модуль `utils.py`:**

1. Функция, возвращающая приветствие в соответствии с временем суток.
2. Функция, считывающая XLSX-файл и выводящая содержимое.
3. Функция, фильтрующая транзакции в диапазоне с начала месяца по текущий день.
4. Функция, фильтрующая транзакции в диапазоне с начала недели по текущий день.
5. Функция, фильтрующая транзакции в диапазоне с начала года по текущий день.
6. Функция, фильтрующая транзакции в диапазоне с самого начала по текущий день.
7. Функция, выдающая номера всех карт.
8. Функция, суммирующая расходы за месяц по каждой карте.
9. Функция, рассчитывающая кэшбэк, исходя из суммы расходов.
10. Функция, возвращающая ТОП-5 транзакций по сумме операции.
11. Функция, возвращающая курс валют из файла `user_settings.json`.
12. Функция, возвращающая курс акций из файла `user_settings.json`.
13. Функция, суммирующая расходы всего.
14. Функция, возвращающая сумму расходов по 7 категориям по убыванию.
15. Функция, возвращающая сумму выдачи наличных и переводов.
16. Функция, возвращающая сумму поступлений.
17. Функция, возвращающая сумму поступлений по категориям по убыванию.

- **Модуль `views.py`:**

1. Функция, "собирающая" все вспомогательные функции для вывода данных для веб-страницы "Главная".
2. Функция, "собирающая" все вспомогательные функции для вывода данных для веб-страницы "События".

- **Модуль `services.py`:**

1. Функция, возвращающая выгодные категории повышенного кэшбэка.
2. Функция, возвращающая сумму, которую удалось бы отложить в "Инвесткопилку".
3. Функция, возвращающая JSON-ответ со всеми транзакциями, содержащими запрос в описании или категории.
4. Функция, возвращающая JSON со всеми транзакциями, содержащими в описании мобильные номера.
5. Функция, возвращающая JSON со всеми транзакциями, которые относятся к переводам физлицам.

1. Функция-декоратор, записывающая результат отчета в файл.
2. Функция, возвращающая траты по заданной категории за последние три месяца (от переданной даты).
3. Функция, возвращающая средние траты в каждый из дней недели за последние три месяца (от переданной даты).
4. Функция, возвращающая средние траты в рабочий и в выходной день за последние три месяца (от переданной даты).

### Страница "События"
Реализован набор функций и главная функция, принимающая на вход строку с датой
и второй необязательный параметр — диапазон данных. 
По умолчанию диапазон равен одному месяцу (с начала месяца, на который выпадает дата, по саму дату).

Возможные значения второго необязательного параметра:

W — неделя, на которую приходится дата;

M — месяц, на который приходится дата;

Y — год, на который приходится дата;

ALL — все данные до указанной даты.

Возвращаемый JSON-ответ содержит следующие данные:

1. **«Расходы»:**
- Общая сумма расходов.
- Раздел «Основные», в котором траты по категориям отсортированы по убыванию.
Данные предоставляются по 7 категориям с наибольшими тратами, траты по остальным категориям
суммируются и попадают в категорию «Остальное».
- Раздел «Переводы и наличные», в котором сумма по категориям «Наличные» и «Переводы» отсортирована по убыванию.
2. **«Поступления»:**
- Общая сумма поступлений.
- Раздел «Основные», в котором поступления по категориям отсортированы по убыванию.
3. **Курс валют.**

### Сервис "Выгодные категории повышенного кешбэка"

Сервис позволяет проанализировать, какие категории были наиболее выгодными для выбора 
в качестве категорий повышенного кешбэка.

Входные параметры:
- data — данные с транзакциями;
- year — год, за который проводится анализ;
- month — месяц, за который проводится анализ.

На выходе — JSON с анализом, сколько на каждой категории можно заработать кешбэка в указанном месяце года:
```json
{
    "Категория 1": 1000,
    "Категория 2": 2000,
    "Категория 3": 500
}
```

### Сервис "Инвесткопилка"

Позволяет копить через округление ваших трат.

Можно задать комфортный порог округления: 10, 50 или 100 ₽. 
Траты будут округляться, и разница между фактической суммой трат по карте
и суммой округления будет попадать на счет «Инвесткопилки».

Входные параметры:

- month — месяц, для которого рассчитывается отложенная сумма (строка в формате 'YYYY-MM').
- transactions — список словарей, содержащий информацию о транзакциях, в которых содержатся следующие поля:

-- Дата операции — дата, когда произошла транзакция (строка в формате 'YYYY-MM-DD').

-- Сумма операции — сумма транзакции в оригинальной валюте (число).
- limit — предел, до которого нужно округлять суммы операций (целое число).

### Сервис "Простой поиск"

Пользователь передает строку для поиска, возвращается JSON-ответ со всеми транзакциями, 
содержащими запрос в описании или категории.

### Сервис "Поиск по телефонным номерам"

Функция возвращает JSON со всеми транзакциями, содержащими в описании мобильные номера.

Например:

- Я МТС +7 921 11-22-33
- Тинькофф Мобайл +7 995 555-55-55
- МТС Mobile +7 981 333-44-55

### Сервис "Поиск переводов физическим лицам"

Функция возвращает JSON со всеми транзакциями, которые относятся к переводам физлицам.

Категория такой транзакции — "Переводы", а в описании есть имя и первая буква фамилии с точкой.

Например:

- Валерий А.
- Сергей З.
- Артем П.

### Отчет "Траты по категории"

Функция принимает на вход:

- датафрейм с транзакциями,
- название категории,
- опциональную дату.

Если дата не передана, то берется текущая дата.

Функция возвращает траты по заданной категории за последние три месяца (от переданной даты).

### Отчет "Траты по дням недели"

Функция принимает на вход:

- датафрейм с транзакциями,
- опциональную дату.

Если дата не передана, то берется текущая дата.

Функция возвращает средние траты в каждый из дней недели за последние три месяца (от переданной даты).

### Отчет "Траты в рабочий/выходной день"

Функция принимает на вход:

- датафрейм с транзакциями,
- опциональную дату.

Если дата не передана, то берется текущая дата.

Функция выводит средние траты в рабочий и в выходной день за последние три месяца (от переданной даты).

## Тестирование
Проект использует библиотеку `pytest` для тестирования.
Все основные модули проекта покрыты тестами, что позволяет обеспечивать стабильность
и надежность кода. Тесты находятся в папке `tests`, и их можно запустить командой:
```commandline
 pytest --cov=src --cov-report=html
 ```

- Покрытие тестами составляет 97%.
- Основные модули, такие как `utils`, `views` и `services` имеют высокий уровень покрытия,
подтверждающий корректность их работы.
- Отчет о покрытии можно найти в папке `htmlcov`, открыв файл `index.html` в браузере.

### Подробности
- Тесты включают проверку всех критических функций.
